### 1 INTRODUCTION
NOTE Avant de lirecedocument, vous devezavoir lu leGuide d’adaptation desSEV(SW-73). Ilprésentelesmodifications nécessaires à apporter pour rendre un système d’enregistrement des ventes (SEV) compatible avec l’environnement technologique mis en place pourpermettreaux exploitantsvisés par les mesuressur la facturation obligatoire de respecter leurs obligations.
1.1 À qui s’adresse ce document?
Cedocuments’adresse à vous si vousavez développé unSEVdans le cadre des mesures sur la facturation obligatoire et que vous devez le faire certifier. Vous y trouverez des renseignements qui vous aideront à réaliser les cas d’essais nécessaires pour obtenir votre certification.
Vous devez le lire attentivement pour réussir votre démarche de certification.
1.2 Quelle version doit être certifiée?
Lapremièreversion de votre SEVdoit être certifiéepour qu’ellepuissecommuniquer avec leMEV-WEB. Pourobtenir votre certification, vous devez réussir une série de cas d’essais. Ceux-ci peuvent être réalisés dans les deux environnements mis à votre disposition (développement et essais).
NOTE Nous vous recommandons de réussir chaque cas d’essais dans l’environnement de développement avant de réaliser votre série de cas d’essais dans l’environnement d’essais.
Lorsque la première version de votre SEV sera certifiée, les versions subséquentes seront permises, à moins d’avis contraire de notre part. Toutefois, chaque version doit faire l’objet d’une nouvelle certification si elle
• contient une nouvelle fonctionnalité; • contient un nouveau support d’impression; • contient un nouveau mode d’opération (SEV ou Serveur); • est adaptée pour une nouvelle version de l’entête HTTP ou de la structure JSON.
Finalement, nous vous recommandons fortement de faire certifier toutes les versions de votre SEV afin de vous assurer que chaque version est compatible avec le MEV-WEB.
Pour obtenir plus de renseignements concernant la certification des SEV, consultez les documents suivants :
• Cas d’essais pour les concepteurs de SEV – Déclaration de conformité (SW-78) • Démarche pour l’obtention d’une certification (SW-79)
NOTE Nous effectuerons certaines vérifications supplémentaires à la suite de la certification de votre SEV afin de nous assurer du respect continu des exigences mentionnées dans le document Entente entre Revenu Québec et le concepteur de produits (SW-10)

3.1 Exécution des cas d’essais
IMPORTANT Avant de commencer les cas d’essais, vous devez avoir en votre possession tous les préalables décrits à la partie 2.1. Vous devez aussi mettre à zéro tous les compteurs de votre SEV. Ainsi, votre SEV ne doit pas avoir de registre de ventes, car un rapport de l’utilisateur sera demandé à la fin des essais.
Pour éviter que votre SEV se déconnecte du MEV-WEB avant d’avoir obtenu une réponse de celui-ci, nous vous demandons de lui allouer un temps d’attente supérieur à 10 secondes.
Ce document contient tous les cas d’essais réalisables, mais vous devez seulement réaliser les cas d’essais relatifs aux fonctionnalités de votre SEV.
Pourfaire certifiervotre SEV, vous devez effectuerlescas d’essais selonvotremode d’opération, en commençant par le cas d’essais présenté àla partie 3.1.1. Pour la suite, c’est le MEV-WEB qui vous indiquera le prochain cas d’essais à réaliser, dans le champ casEssai inclus dans sa réponse, jusqu’à la fin de la sériedes cas d’essais.
NOTE Si votre SEV offre plusieurs supports d’impression, le quatrième chiffre du cas d’essais à réaliser (ex. : 011.201) vous indiquera le support d’impression que vous devez utiliser.
Notez que les cas d’essais sont divisés en quatre blocs qui doivent être réalisés séquentiellement, selon le type de requête. L’ordre des blocs de cas d’essais est le suivant :
1. Bloc pour les requêtes de type « certificats » 2. Bloc pour les requêtes de type « utilisateur » 3. Bloc pour les requêtes de type « transaction » 4. Bloc pour les requêtes de type « document »
IMPORTANT Sivotre produit peut fonctionneren mode SEV et Serveur, vous devez réaliser les cas d’essaisdumodeSEV avant de réaliser ceux du mode Serveur, en alternant chaque bloc de cas d’essais. Par exemple, vous devez obtenir les certificats pour votre SEV et ensuite obtenir les certificats pour le serveur tiers avant de commencer le bloc de cas d’essais suivant.
3.1.1 Premier cas d’essais
Si le mode d’opération de votre produit est le mode Serveur, vous devez commencer par le cas 500 (voyez la partie 3.2.1). Après avoir réussi le premier bloc, vous allez pouvoir poursuivre avec le suivant.
Si le mode d’opération de votre produit est le mode SEV, vous devez commencer par lecas001(voyezlapartie 3.2.2). Après avoir réussi le premier bloc, vous allez pouvoir poursuivre avec le suivant.
Si votre produit peut fonctionner en mode SEV et en mode Serveur, vous devez commencer par le cas 500. Après avoir réussi le premier bloc, vous allez pouvoir poursuivre avec le suivant.
NOTE Les identifiants des cas d’essais qui concernent le mode SEV débutent par le chiffre 1 (ex. : 101), alors que les identifiants qui concernent le mode Serveur débutent par le chiffre 5 (ex. : 501). Par ailleurs, si le nom d’un champ est écrit en lettres majuscules, cela signifie qu’il s’agit d’un champ d’entête HTTP.

3.1.2 Cas d’essais échoué
Si vous échouez à un cas d’essais, vous devrez recommencer le bloc de cas d’essais en cours de réalisation. Le MEV-WEB transmettra une liste d’erreurs dans sa réponse, ainsi que le numéro du cas d’essais où vous devrez recommencer.

Notez que vous pouvez recommencer vos cas d’essais depuis le début même si vous avez réalisé le dernier cas d’essais qui vous était demandé et que vous avez reçu une réponse du MEV-WEB contenant le numéro 999.999. IMPORTANT Si vous voyez le symbole dans les étapes d’un cas d’essais, cela signifie que vous devez enregistrer une copie du document en format PDF, qu’il soit en support papier ou électronique. Le nom du document doit être identique à la valeur du champ d’entête CASESSAI (ex. : 011.201.pdf).
